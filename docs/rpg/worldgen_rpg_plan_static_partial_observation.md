# Static Partially Observed RPG Worlds — v2 Plan

> Supersedes the time-based design in `worldgen_rpg_plan.md`. Everything below
> still ships in `world_gen_rpg.py` and is named `*_rpg_*` to stay consistent
> with the existing simulator/audit pipeline.

## 0. What this plan is

A discovery benchmark where an LLM "scientist" must explain a population that
already shows a problem (or an opportunity) and propose what to do about it.
The agent is **not** handed a menu of candidate policies. The world only
exposes a set of *intervenable knobs* and a set of *observable measurements*;
the agent has to decide what to measure, what to intervene on, how to interpret
noisy signals, and what hypothesis fits.

The two guiding examples we want this to support cleanly:

- **H. pylori-style hidden cause.** A population has a disease. The prevailing
  theory (stress / acid / lifestyle) is a red herring. The latent driver is a
  bacterial colonization, and the only intervention that helps is a course of
  antibiotics, which conventional wisdom says is irrelevant. The agent has to
  ignore the prior and discover the latent cause.
- **Fraud-anomaly discovery.** Most units in a population follow a structured
  generative process. A small subset is generated by a different process
  (fraud, error, attack). The agent has to characterize the anomaly from noisy
  multivariate measurements and identify the units that belong to it.

These are different shapes of question — the first asks "what should you do?",
the second asks "what's going on?" — and the plan keeps both first-class.

## 1. Hard design rules

1. **No action menu.** Worlds expose intervenable variables, not pre-named
   policies. The agent constructs interventions as `do({var: value, ...})`.
   Some intervenable variables are red herrings.
2. **Hidden ≠ visible.** Every world has latent variables that drive the
   outcome and are never revealed to the agent or shown in the story.
3. **All measurements are noisy.** No proxy is a clean readout. Several
   measurements are multi-cause.
4. **One mechanism, one truth.** Agent samples, oracle scoring, validators,
   and audits share the same `apply_intervention` and `observe` functions.
5. **Brute force should fail.** Cell budget plus per-query column caps must
   force the agent to choose measurements and interventions by hypothesis,
   not by spraying queries.
6. **Naive answer schemas are banned.** No "pick policy_A/B/C/D". Answers are
   structured discoveries: an intervention dict, a conditional policy, an
   anomaly rule, etc.
7. **No leakage through names.** Story and variable names are neutral. The
   latent role of any variable is in `hidden`, never in the visible block.
8. **Static, no time.** No `horizon`, no rollouts. Outcomes are
   one-shot potential outcomes under `do(.)`.
9. **Mixture prior, but called what it is.** A `(1 − ρ)` structured / `ρ`
   uniform mixture exists for robustness to outliers and to dilute overly
   clean correlations. It is *not* the primary partial-observability lever —
   noise and multi-cause proxies are.

## 2. World object

A static RPG world is:

```text
W = (Z, X, K, U, Theta, F, H, P_unit, Q, O, V)
```

- `Z` — hidden latent variables (severity, subtype, presence-of-latent-cause,
  benefit-response, harm-sensitivity, etc.).
- `X` — observable measurements. Always noisy. Some multi-cause.
- `K` — intervenable knobs. Categorical or scalar. **Includes red herrings.**
- `U` — hidden unit parameters (background risk, propensity, etc.).
- `Theta` — world-level parameters (effect sizes, noise sigmas, mixture ρ,
  prevalence of latent cause, etc.).
- `F` — structural equations for outcomes under `do(k = v)`. Computes the
  full potential outcomes table `Y_i(k)` for every action choice.
- `H` — observation equations: hidden → visible measurement with noise.
- `P_unit` — `(1 − ρ)` structured population + `ρ` uniform-mixture units.
- `Q` — question(s). One primary question per world; optional secondary.
- `O` — oracle objective. Scored by Monte Carlo over `Y_i(k)`.
- `V` — validators (signature + recoverability band).

For each sampled unit:

```text
B_i  ~ Bernoulli(ρ)
U_i  ~ structured if B_i = 0, else uniform
Z_i  = f_z(U_i, ε_i)
X_i  = h(Z_i, U_i, η_i)
Y_i(k) = f_y(Z_i, U_i, k, ξ_i)    # full potential-outcomes row
```

The key simulator primitive is **`apply_interventions(hidden, action_dict)`**,
which returns `Y, Harm, Metric` for every unit under the requested
intervention. It is called the same way by:

- the agent's `interventional_sample` queries,
- the oracle's high-budget scoring,
- the validator's signature recomputations.

There is exactly one code path.

## 3. Query interface (agent-facing)

Three modes, no time axis, no policy ids:

### 3.1 `observational_sample`

Returns measurements under the world's "current practice" intervention
assignment, which is a hidden function of latent severity / unit context.
Used to inspect the natural distribution and to set up the
confounding-reversal test.

```json
{
  "mode": "observational_sample",
  "n_units": 200,
  "measurements": ["BiomarkerA", "SymptomScore"]
}
```

### 3.2 `interventional_sample`

Returns measurements under `do(intervention)` applied uniformly to all units.

```json
{
  "mode": "interventional_sample",
  "intervention": {"AntibioticCourse": "on"},
  "n_units": 200,
  "measurements": ["UlcerSeverityProbe", "InflammationMarker"]
}
```

`intervention` is a dict mapping intervenable-knob names to values. The
simulator rejects:

- a non-intervenable variable name in the dict,
- an unknown variable name,
- a value outside the variable's declared domain.

Rejection is verbose so the agent can correct itself.

### 3.3 `inspect_unit` (case-level)

Returns the full set of allowed measurements for one freshly sampled unit
under observational assignment. Useful for the anomaly archetype, which
requires per-unit access.

```json
{
  "mode": "inspect_unit",
  "case_seed": 17,
  "measurements": ["FeatureA", "FeatureB", "FeatureC"]
}
```

A `case_seed` makes one specific unit replayable.

### 3.4 Budget

Cell accounting with per-query column cap:

```text
cost = n_units × n_columns
n_columns = len(measurements) + len(intervention_dict) + bookkeeping(2)
```

Suggested defaults:

```json
{
  "sample_accounting": "cells",
  "max_total_samples": 12000,
  "max_samples_per_query": 4000,
  "max_units_per_query": 400,
  "max_measurements_per_query": 3,
  "max_queries": 8
}
```

These numbers are tight by design. A naive "sweep every intervention with all
measurements at max n" exceeds budget in one query. The agent must choose
what to measure.

## 4. Answer schemas

Answers are **structured discoveries**, never single tokens. Each question
declares an `answer_schema`. The two we use in v1:

### 4.1 `intervention_with_hypothesis`

```json
{
  "intervention": {"AntibioticCourse": "on"},
  "hypothesis": "Free-form English description of the proposed mechanism."
}
```

- `intervention`: dict over intervenable knobs. Required. Scored.
- `hypothesis`: required but **not auto-scored in v1**. It is preserved in
  the trajectory so we can audit reasoning quality later (LLM-judged or
  human-judged).

The intervention is scored by re-running the simulator under
`do(agent_intervention)` and comparing the resulting target distribution to
the gold intervention's. An agent intervention is accepted if its expected
utility is within `oracle_tolerance` of the gold's expected utility. The
runner-up's expected utility plus margin defines what "close enough" means.

### 4.2 `anomaly_identification`

```json
{
  "anomaly_rule": "FeatureA > 70 AND FeatureC < 30",
  "flagged_unit_ids": [3, 18, 41, 92, 117]
}
```

- `flagged_unit_ids`: required. Scored against the hidden anomaly indicator
  by precision and recall over a held-out audit batch the oracle samples
  fresh. Threshold: precision ≥ 0.7 and recall ≥ 0.6 (tunable).
- `anomaly_rule`: required but **not auto-scored in v1** (LLM-judge later).

A world declares exactly one primary question. Some worlds may also include
a secondary "mechanism check" question that uses the same simulator and the
same budget. Multi-question worlds are allowed when the second question
strictly raises the bar (e.g. the same world asks both "what intervention?"
and "would do(X=v) on this proxy help?" — testing the validity of a
seductive but wrong intervention).

## 5. Archetypes (v1: two; v1.5: four)

We start small and only ship archetypes that test a clearly distinct
scientific ability. Things deferred indefinitely: pure proxy-metric hacking
(too close to confounded_action without adding new ability), mediator-vs-
direct-effect (too close to existing advanced-bench mechanics).

### Archetype A — `rpg_hidden_cause` (v2.1, shipped)

**Scientific ability:** discover a latent variable that explains the
phenomenon, ignore an entrenched but wrong prior, intervene on a
counter-intuitive knob. The world must be hard enough that name-pattern
matching does NOT solve it.

**Setup.** A population has a chronic problem (high target-bad-state). Four
intervenable knobs exist: two decoys tied to the prevailing wrong theory,
one palliative (suppresses the visible symptom score without addressing
the cause), and one **neutrally-named** true lever that acts on a hidden
continuous burden. The agent sees noisy proxies of: target severity, two
decoy mechanisms, and a neutrally-named lab panel that is informative
about the true cause but never labelled as such.

**Hidden structure (v2.1 — all continuous; decoys observationally coupled).**

```text
LatentBurden       ~ N(burden_mean, burden_sd) clipped 0-100
                     The TRUE cause. Drives the target through a soft
                     sigmoid-threshold so the lever has the biggest effect
                     in the active band.

BurdenSubstrate    ~ N(substrate_mean, substrate_sd) clipped 0-100
                     The OBSERVATIONAL CONFOUND. Drives both decoy states
                     AND raises BaselineSeverity. Independent of LatentBurden,
                     so the true_lever has no effect on it.

HealthSeekingTrait ~ N(healthseek_mean, healthseek_sd) clipped 0-100
                     The ASSIGNMENT CONFOUND. Drives uptake of non-baseline
                     knobs in current practice; lowers BaselineSeverity.

DecoyState_{A,B}   = a + b * BurdenSubstrate + noise
BaselineSeverity   = c + sub_loading * BurdenSubstrate
                       - hs_loading * (HealthSeekingTrait - hs_mean)
                       + noise
TargetSeverity     = BaselineSeverity
                     + burden_effect * sigmoid((LatentBurden - threshold)/soft)
                                     * (LatentBurden / 100)
                     + noise
```

This shape gives:
- decoy_proxy ↔ target observed correlation in `[0.20, 0.35]` (genuinely tempting),
- latent_driver_proxy ↔ target observed correlation in `[0.30, 0.45]` (informative but noisy),
- decoy interventions: zero do-effect on target (they only move decoy state),
- true lever intervention: multiplicatively reduces LatentBurden,
  dropping target by 10-20 units.

**Anti-pattern-match templates.** The latent_driver_proxy name is neutral
(`IntakeSerumPanelB`, `OrchardLabPanel3`, `RiskSignalCluster7`) and the
true_lever_knob name is neutral (`OralRegimenM`, `FieldTreatmentF`,
`RiskRuleR4`). Decoy proxies and decoy knobs continue to share the
prevailing-theory vocabulary (`StressInventoryScore` ↔
`StressReductionProgram`), so an LLM that pattern-matches names is
*actively misled*.

**Intervenable knobs (example).**

```text
StressReductionProgram     # red herring (moves DecoyState1, no Y effect)
DietModification           # red herring (moves DecoyState2, no Y effect)
AntacidDose                # weak effect: damps symptom proxy, not target
AntibioticCourse           # TRUE LEVER: clears LatentDriver
NoIntervention             # baseline
```

The intervention is multi-valued (categorical or `[off, low, high]`). At
least one decoy knob is *just as visible* in observational data as the true
knob, so naive correlational reasoning fails.

**Observed measurements.**

```text
SymptomReport              # noisy proxy of TargetSeverity
ImagingScore               # noisy proxy of TargetSeverity
SerologyMarker             # noisy weak proxy of LatentDriver (not labeled as such)
DecoyMarker1, DecoyMarker2 # noisy proxies of the decoy states
SecondaryOutcome           # independent target proxy for cross-check
```

**Question.**

> "A population shows persistent high SymptomReport. Propose the single
> intervention that most reduces SymptomReport on a freshly sampled
> population. Return both your intervention and a one-paragraph hypothesis
> for the underlying mechanism."

Answer schema: `intervention_with_hypothesis`. The intervention dict must
include exactly one knob (`max_intervention_knobs = 1` for this archetype).

**Gold.**

```text
gold_intervention = argmax_k E[ -TargetSeverity(k) ]
gold_margin       = E[Y(gold)] − E[Y(runner_up)]
```

The runner-up must be a red-herring intervention so the gold margin is over
a *tempting* alternative, not over `NoIntervention`.

**Validators.**

- `latent_driver_present`: at least 35% of units carry the latent driver in
  the mixed population.
- `decoy_obs_correlation`: `corr(DecoyMarker1, SymptomReport)` ≥ 0.35 in
  observational data, so the decoy is visibly tempting.
- `obs_truth_misleading`: in observational data, intervention assignment
  rates make at least one decoy intervention look as good as the true one.
- `true_lever_dominates_interventional`: under `do(true_lever)` the
  target improvement beats every other knob's interventional effect by
  `gold_margin ≥ MIN_GOLD_MARGIN`.
- `serology_is_informative_not_perfect`:
  `0.35 ≤ corr(SerologyMarker, LatentDriver) ≤ 0.85`.
- `recoverability_band`: a "small-budget naive baseline" (e.g. 80 units of
  observational data) recovers gold ≤ 40% of seeds; a "medium-budget naive
  baseline" (e.g. 400 units under each candidate intervention, using only
  SymptomReport) recovers gold ≥ 70% of seeds. Defines the difficulty
  window where discovery matters.

### Archetype B — `rpg_confounded_action` (v1)

**Scientific ability:** recognize that observational evidence is biased,
design an intervention to identify the true effect, and act on the sign-
reversed conclusion.

**Setup.** An entrenched practice assigns an intervention to units with high
latent severity. Observational data therefore shows that "the intervention
correlates with bad outcomes." Under uniform `do(intervention=on)` the
intervention strictly improves the latent target. The right answer is to
intervene; the wrong answer (which fits the passive data) is not to.

**Hidden structure.**

```text
LatentSeverity ~ structured mixture
Assignment      = 1 if (LatentSeverity > θ_assign + noise) else 0   # confounded
TrueEffect      = positive monotone in intervention level
Y(k)            = baseline − severity_penalty(LatentSeverity)
                  + true_effect(k) + noise
```

**Intervenable knobs.**

```text
Treatment   in {off, low, high}
SupportiveCare in {off, on}   # weakly helpful, looks unconfounded
NoIntervention                # baseline
```

`SupportiveCare` is included so the agent has a second, *non-sign-reversed*
choice — the test is whether they correctly upgrade from supportive care to
the apparently-harmful but actually-helpful treatment.

**Observed measurements.**

```text
SeverityProxyA, SeverityProxyB    # noisy proxies of LatentSeverity
TargetOutcomeProxy                # noisy proxy of Y
AssignmentRecord                  # what the unit actually received in obs data
```

**Question.**

> "A common belief in this population is that Treatment leads to worse
> outcomes. Propose the intervention that maximizes TargetOutcomeProxy on a
> freshly assigned population, and explain in one paragraph whether and why
> the prevailing belief is mistaken."

Answer schema: `intervention_with_hypothesis`. Intervention may set both
`Treatment` and `SupportiveCare`. `max_intervention_knobs = 2`.

**Gold.**

```text
gold_intervention = argmax_k E[ Y(k) ]   under do(k)
```

Validators must ensure: gold is `Treatment=high` (plus optional
`SupportiveCare=on`); observational sign on `Treatment` is *negative*; gold
margin over `NoIntervention` ≥ `MIN_GOLD_MARGIN`; severity proxies are
informative but imperfect.

### Archetype C — `rpg_hidden_subtype` (v1.5)

**Scientific ability:** detect hidden heterogeneity from a noisy classifier
proxy, propose an intervention policy *conditional* on that proxy. Tests
contextual-bandit-style reasoning under partial observability — bridge to
the later RL phase.

**Setup.** Two latent subtypes exist with prevalence `(π, 1 − π)` where
`π ∈ [0.40, 0.60]`. Three candidate interventions are offered. Subtype 0
responds best to intervention A, subtype 1 to intervention C, intervention
B is a moderate compromise. A noisy `SubtypeScreen` proxy is right with
probability `r ∈ [0.70, 0.90]`. The "best static intervention" (the one
that maximizes population mean) is strictly worse than the conditional
policy keyed on the screen.

**Hidden structure.**

```text
LatentSubtype ~ Bernoulli(π)
HarmSensitivity ~ Normal(50, 15) clipped 0-100
BaselineRisk ~ Normal(50, 18) clipped 0-100
Y(k, subtype) = baseline(k) + subtype_effect[k, subtype]
              + lambda_baseline_risk * BaselineRisk + noise
```

**Intervenable knobs.**

```text
TreatmentA ∈ {off, on}
TreatmentB ∈ {off, on}
TreatmentC ∈ {off, on}
```

`max_intervention_knobs = 1` for the static-best version; the conditional
policy answer schema allows two knobs (one per branch).

**Observed measurements.**

```text
SubtypeScreen          # noisy 0-100 classifier proxy of LatentSubtype
SecondarySubtypeScreen # weaker independent classifier
BaselineRiskProxy
TargetOutcomeProxy     # noisy proxy of Y(k, subtype)
SecondaryOutcomeProxy
```

**Question.**

> "Different units in this population respond differently to the same
> intervention. Propose a policy that maps the observable
> `SubtypeScreen` (or a similar proxy) to one intervention from
> {TreatmentA, TreatmentB, TreatmentC}, and explain the heterogeneity."

**Answer schema: `conditional_policy`.**

```json
{
  "branch_variable": "SubtypeScreen",
  "branch_threshold": 50.0,
  "if_above": {"TreatmentC": "on"},
  "if_below": {"TreatmentA": "on"},
  "hypothesis": "..."
}
```

Schema rules:
- `branch_variable` must be one of the observed variables.
- `branch_threshold` is on the 0-100 scale.
- `if_above` / `if_below` are each a `do(.)` dict with at most one knob.
- Scoring: oracle simulates the policy by sampling units, applying the
  matched intervention per unit, and computing expected utility. Accepted
  if within `oracle_tolerance` of the gold policy.

**Gold.**

```text
gold_policy = argmax over (branch_variable, threshold, k_above, k_below)
              of E[ Y(policy(X)) ]
```

Search space is small (a handful of candidate screens × threshold grid ×
intervention pairs) and oracle-evaluable by Monte Carlo.

**Validators.**

- `subtype_screen_informative`:
  `0.70 ≤ P(SubtypeScreen ≥ θ | LatentSubtype = 1) ≤ 0.90`.
- `subtype_effects_differ`:
  `|Y(A, 0) − Y(A, 1)| ≥ MIN_SUBTYPE_GAP` and same for C.
- `conditional_beats_static`:
  `E[Y(gold_policy)] − E[Y(best_static)] ≥ MIN_CONDITIONAL_GAIN`.
- `subtype_prevalence`: `0.40 ≤ π ≤ 0.60`.
- `recoverability_band`: small obs naive miss, medium intv-per-stratum
  hit (sample per (screen-bucket, intervention) cell at medium budget).

### Archetype D — `rpg_anomaly_discovery` (v1.5)

**Scientific ability:** identify a small subpopulation generated by a
different process; characterize what makes the anomaly different.

**Setup.** `(1 − π)` of units come from a structured "normal" generative
process. `π ∈ [0.04, 0.10]` of units come from an "anomaly" process with
a different joint distribution over a subset of features. The agent must
flag the anomalous unit ids and (optionally) describe the rule.

There is **no intervention** — this archetype tests partial-observability
skills on a *discovery* question, not an action question.

**Hidden structure.**

```text
B_i ~ Bernoulli(π)                    # anomaly indicator
if B_i = 0: features ~ normal_generator(...)
if B_i = 1: features ~ anomaly_generator(...)
```

The anomaly generator differs on a *subset* of features, often as a
shift in mean of a multivariate Gaussian or a flip of a binary marker.
The discriminating subset is the gold signature.

**Observed measurements (example: payment fraud domain).**

```text
TxAmountQuantile        # 0-100
TxFrequencyDeviation    # 0-100
DeviceTrustScore        # 0-100
GeoVelocityIndex        # 0-100
SecondaryRiskSignal     # 0-100
UnitIdentifier          # integer unit_id, returned with every row
```

**Question.**

> "Most accounts in this population follow a stable behavioral pattern;
> a small number do not. Identify which observed units belong to the
> anomalous group, and describe how the anomalous behavior differs."

**Answer schema: `anomaly_identification`.**

```json
{
  "flagged_unit_ids": [3, 18, 41, 92, 117],
  "anomaly_rule": "GeoVelocityIndex > 70 AND DeviceTrustScore < 30",
  "hypothesis": "..."
}
```

Schema rules:
- `flagged_unit_ids` must be ids the agent actually observed via prior
  queries (the simulator stores the union of returned unit ids per
  query).
- `anomaly_rule` is required text; not auto-scored in v1.5 (judge later).
- Scoring: the oracle samples a fresh `audit_batch` of `N_audit = 2000`
  units. The agent's `anomaly_rule` is parsed (simple `> < AND OR`
  grammar) and applied to the audit batch's observations; the resulting
  precision/recall against the hidden anomaly indicator is the score.
  If the rule fails to parse, fall back to scoring just the flagged_unit_ids
  among the queried set (precision/recall on observed units only).
- Acceptance: `precision ≥ 0.7` AND `recall ≥ 0.6`.

**Gold.**

The gold anomaly signature is stored as a sklearn-style decision
function from the hidden generators. Oracle precision/recall under the
gold rule on `audit_batch` must hit `≥ 0.85 / ≥ 0.80`.

**Validators.**

- `anomaly_prevalence`: `0.04 ≤ π ≤ 0.10`.
- `feature_separation`: at least two features have
  `|mean_anomaly − mean_normal| ≥ FEATURE_SHIFT_THRESHOLD`.
- `single_feature_insufficient`: no single feature reaches
  `precision ≥ 0.85` AND `recall ≥ 0.80` by itself — the agent must
  combine signals.
- `recoverability_band`: small-budget naive (single-feature thresholding
  on 80 observed units) misses; medium-budget naive (multivariate
  Mahalanobis distance on 400 observed units) hits.

### Archetype E — `rpg_mechanism_chain` (v2)

**Scientific ability:** locate the actual bottleneck step in a multi-stage
causal chain. The chain is visible (the stages are named and intervenable)
but which stage is the binding constraint is hidden behind noisy stage
proxies. Tests root-cause analysis under partial observability.

**Setup.** Three or four sequential stages produce a final outcome:
`Stage1 → Stage2 → Stage3 → Y`. Each stage has an intrinsic "yield rate"
hidden from the agent. Stages with high yield rate are not the bottleneck;
intervening on them barely moves Y. The bottleneck stage has low yield
rate; intervening on it moves Y substantially. The bottleneck is hidden:
sometimes Stage1, sometimes Stage2, sometimes Stage3, selected per world.

**Hidden structure.**

```text
yield_1, yield_2, yield_3 ~ Beta(...)        # latent stage yields
bottleneck = argmin(yield_1, yield_2, yield_3)
Y = K * prod(yield_i^{1 - intervention_i})   # intervening at stage i raises its effective yield
```

**Intervenable knobs.**

```text
Stage1Intervention ∈ {off, on}
Stage2Intervention ∈ {off, on}
Stage3Intervention ∈ {off, on}
```

`max_intervention_knobs = 1`.

**Observed measurements.**

```text
Stage1Throughput   # noisy proxy of yield_1
Stage2Throughput   # noisy proxy of yield_2
Stage3Throughput   # noisy proxy of yield_3
FinalOutcomeProxy  # noisy proxy of Y
SecondaryOutcomeProxy
```

The throughput proxies are noisy enough that you can't pick the bottleneck
from a single small observational batch — but they're informative under
interventional sampling.

**Question.**

> "This pipeline has three observable stages. Performance is below target.
> Identify which single stage is the bottleneck and propose an
> intervention there. Explain why the other stages are not the right
> place to intervene."

**Answer schema: `intervention_with_hypothesis`** (same as hidden_cause).

**Gold.**

```text
gold_intervention = {Stage<bottleneck>Intervention: "on"}
gold_margin = E[Y(do(bottleneck=on))] − E[Y(do(second_lowest=on))]
```

**Validators.**

- `bottleneck_unique`: the lowest yield is at least `δ_yield = 0.10`
  below the second-lowest, so the bottleneck is well-defined.
- `non_bottleneck_interventions_weak`:
  `E[Y(do(non_bottleneck))] − E[Y(NoIntervention)] ≤ MIN_NON_BOTTLENECK_GAIN`.
- `bottleneck_intervention_strong`:
  `E[Y(do(bottleneck))] − E[Y(NoIntervention)] ≥ MIN_BOTTLENECK_GAIN`.
- `throughput_proxies_informative`:
  `0.30 ≤ corr(StageIThroughput, yield_i) ≤ 0.85`.
- `recoverability_band`: small obs naive (pick the stage whose throughput
  proxy correlates most strongly with the outcome proxy at 80 units)
  often picks the wrong stage; medium intv naive (test each stage's
  intervention at 400 units each) picks the bottleneck.

Bottleneck selection is balanced across worlds (1/3 each on Stage1,
Stage2, Stage3) so no positional bias.

### Archetype F — `rpg_negative_control` (v2)

**Scientific ability:** recognize that none of the popular available
interventions actually works, despite observational data suggesting one
does. Submit `NoIntervention` with a hypothesis that explains the
spurious effect (regression to mean, selection, fad correlation).

**Setup.** A "trendy" intervention has been widely promoted. Observational
data shows people who use it have better outcomes. Under `do(.)` for every
non-baseline intervention, the latent target moves by less than the gold
margin from baseline — i.e., *nothing actually works*. The apparent
observational benefit comes from `HealthSeekingTrait`-style confound: the
trendy intervention is used disproportionately by units with intrinsically
better outcomes.

**Hidden structure.** Same shape as `hidden_cause`'s hidden block, but with
`driver_effect = 0` and `true_lever_on_driver_clearance = 0`. The latent
driver may even be absent (`p_driver_present = 0`). Every intervention's
true do-effect on Y is below the gold margin.

**Intervenable knobs.**

```text
TrendyIntervention ∈ {off, on}
ConventionalAlternative ∈ {off, on}
ResearchBackedOption ∈ {off, low, high}
NoIntervention is the default (encoded as all knobs = off / off / off)
```

The knob *descriptions* in templates are all positively-framed and
plausible. The LLM polish hook is explicitly told (via the
`_STATIC_ARCHETYPE_BRIEF[negative_control]` line) to maintain this
ambiguity.

**Observed measurements.**

```text
PrimaryOutcomeProxy    # noisy
SecondaryOutcomeProxy  # independent noisy
WellbeingProxy
EngagementProxy
HealthSeekingProxy     # noisy proxy of the confounder
```

**Question.**

> "This population has access to several widely discussed interventions.
> Determine which intervention should be applied uniformly to a freshly
> sampled population to improve PrimaryOutcomeProxy. If no intervention
> reliably improves the outcome, return an empty intervention dict
> `{}` and explain why the observational data is misleading."

**Answer schema: `intervention_with_hypothesis`**, accepting the empty
intervention `{}` as a valid answer.

**Gold.**

`gold_intervention = {}` (NoIntervention). The runner-up is the
empirically-best non-baseline intervention; the margin is `E[Y(NoInt)] −
E[Y(runner_up)]`, where the runner_up is at most `MIN_NEG_CTRL_GAP` better
or worse than baseline.

Critical design constraint: every non-baseline intervention's do-effect
must be within ±`MIN_NEG_CTRL_GAP` of baseline. Otherwise, the world is
just a normal hidden_cause / confounded_action and not a negative-control
test.

**Validators.**

- `no_intervention_actually_works`:
  `max_k |E[Y(do(k))] − E[Y(NoIntervention)]| < MIN_NEG_CTRL_GAP`.
- `observational_effect_strong`: at least one intervention has
  `E[Y | TrendyIntervention=on, obs] − E[Y | TrendyIntervention=off, obs] ≥ 6.0`.
- `confound_drives_apparent_effect`: the obs effect on `TrendyIntervention`
  must shrink to within `±MIN_NEG_CTRL_GAP` after stratifying on
  `HealthSeekingProxy` quartiles.
- `recoverability_band`: small obs naive picks the trendy intervention;
  medium intv naive picks NoIntervention because no intervention beats
  baseline by margin.

### 5.5 Validation playbook (common to all archetypes)

Every archetype passes through the same six-stage gate before a world is
written to disk:

1. **Mechanism signature**: archetype-specific check(s) confirming the
   world has the intended shape (e.g. `true_lever_is_gold`,
   `observational_sign_negative`, `bottleneck_unique`,
   `no_intervention_actually_works`).
2. **Gold margin**: `E[Y(gold)] − E[Y(runner_up)] ≥ STATIC_MIN_GOLD_MARGIN`.
   Margin computed under CRN to keep SE tight.
3. **Recoverability band**:
   `small_budget_naive_hit_rate ≤ STATIC_RECOVER_SMALL_MAX` AND
   `medium_budget_naive_hit_rate ≥ STATIC_RECOVER_MEDIUM_MIN`. Naive
   baseline varies per archetype (declared in
   `_static_recoverability_band` archetype dispatch).
4. **Leakage check**: no hidden variable name / role word in
   `visible.story` / `visible.observed_variables[*].description` /
   `visible.question`. Substring blacklist + variable-name preservation.
5. **Reproducibility**: rerun `_static_oracle_score` with a different
   seed; gold ordering of top-3 candidates must be stable. Oracle SE
   must be `≤ MAX_ORACLE_SE_FRACTION × gold_margin`.
6. **Schema/visibility split**: visible block contains only agent-facing
   variables; hidden block contains everything else; oracle/validators
   are present and consistent.

Any failure rejects the world; the generator retries with a fresh seed up
to `max_attempts_per_world` times.

### 5.6 Templating strategy across archetypes

Every archetype splits content cleanly between **mechanism** (code-owned)
and **template** (data, optionally LLM-proposed).

A template is a dict with:

- `topic`, `subdomain`, `setting` (the neutral story framing),
- `unit` (e.g. patient / user / orchard block / pipeline stage),
- `names`: a dict mapping role keys to CamelCase variable names,
- `knob_descriptions`: every intervenable variable name → neutral
  one-sentence description,
- `measurement_descriptions`: every observed variable name → neutral
  one-sentence description.

Role keys are archetype-specific and defined in
`_static_required_template_keys`:

| Archetype | Role keys |
|---|---|
| `hidden_cause` | `primary_target_obs`, `secondary_target_obs`, `latent_driver_proxy`, `decoy_proxy_a`, `decoy_proxy_b`, `tertiary_obs`, `decoy_knob_a`, `decoy_knob_b`, `weak_knob`, `true_lever_knob` |
| `confounded_action` | `primary_target_obs`, `severity_proxy_a`, `severity_proxy_b`, `secondary_target_obs`, `assignment_record`, `treatment_knob`, `support_knob` |
| `hidden_subtype` | `target_obs`, `secondary_target_obs`, `subtype_proxy`, `secondary_subtype_proxy`, `baseline_risk_proxy`, `treatment_a_knob`, `treatment_b_knob`, `treatment_c_knob` |
| `anomaly_discovery` | `target_obs`, `feature_a`, `feature_b`, `feature_c`, `feature_d`, `secondary_signal` |
| `mechanism_chain` | `final_outcome_obs`, `secondary_outcome_obs`, `stage_1_proxy`, `stage_2_proxy`, `stage_3_proxy`, `stage_1_knob`, `stage_2_knob`, `stage_3_knob` |
| `negative_control` | `primary_outcome_obs`, `secondary_outcome_obs`, `wellbeing_proxy`, `engagement_proxy`, `healthseeking_proxy`, `trendy_knob`, `conventional_knob`, `research_backed_knob` |

The mechanism never reads `names[k]` directly except to insert into the
visible block; it reads role keys. So a new template only needs to fill
in the names + descriptions and the mechanism Just Works.

**Hand-written templates** for each archetype: 3 minimum. These anchor
diversity for domain-specific reviewers and act as schema references
for the LLM proposer.

**LLM-proposed templates** via `_static_llm_propose_template`: when
`--llm-extra-templates N` is set, Opus 4.8 invents N additional templates
per archetype. The brief, the role keys, an example template, and the
avoid-list (already-used subdomains) go in; one JSON template comes out
and is validated by `_static_template_validate`. Mechanism stays
code-owned; only the names + scenarios are LLM-invented.

**What the LLM is never asked to do at template time:**

- Decide which role key is the "true lever" or the "bottleneck" or the
  "anomaly generator." Roles are fixed by code.
- Set effect sizes, noise SDs, mixture weight, or anything that affects
  the gold answer.
- Choose answer schema or validators.

### 5.6a How we keep LLM-proposed templates *mechanism-coherent*

Templates that only carry role *keys* (`true_lever_knob`, `decoy_knob_a`,
…) and ask the LLM to pick names give the LLM no way to know what each
role *means* in the underlying mechanism. The result would be
nonsensical: the mechanism code that operates on `true_lever_knob` could
end up wired to an invented name like `RoutineHandwashing` even when the
scenario is "orchard yield." That isn't a leak (the agent doesn't see
the role label), but it makes the world incoherent — descriptions
won't match the do-effects the simulator actually applies.

The fix is `_static_role_briefs(archetype)` — a per-role *semantic brief*
that the LLM consumes at proposal time. Each brief explains, in plain
language, what kind of construct, intervention, or measurement that role
represents in the mechanism. For example, `hidden_cause` includes:

- `true_lever_knob`: *"A binary unconventional intervention that the
  prevailing theory does NOT emphasize, but which actually acts on the
  hidden construct (e.g. antibiotics for ulcers, TLS-fingerprint gate
  for fraud, root-zone fungicide for orchard yield). Its name and
  description must NOT signal 'this is the answer'."*
- `weak_knob`: *"A discrete-level palliative intervention (off / low /
  high) that suppresses the visible primary_target_obs reading without
  changing the underlying construct. Should sound symptomatic, not
  root-cause."*
- `decoy_proxy_a`: *"A 0-100 measurement aligned with one pillar of the
  popular prevailing theory (e.g. stress for ulcers; device quality for
  chargebacks)."*

These briefs are passed to the LLM at template-proposal time only. The
agent never sees them — the only thing that reaches `visible` is the
neutral one-sentence description the LLM produces. The proposer prompt
explicitly says: *"do NOT echo the meanings (or words like 'decoy',
'true lever', 'palliative') into your output."*

Two safeguards on top of the briefs:

1. **Substring leakage check** (`_static_leakage_check`) rejects any
   template whose visible content uses banned role words.
2. **Mechanism-level validators run after the template is wired in.**
   If the LLM's invented `weak_knob` somehow doesn't actually act
   palliatively in the apply equations, the recoverability band will
   detect the mismatch (the small-budget naive baseline's failure mode
   depends on the palliative being palliative) and reject the world.

So coherence is enforced at three layers: the brief tells the LLM what
to invent; the leakage check stops the brief from being echoed; the
validation playbook (§5.5) refuses to write a world where the resulting
mechanism + descriptions are inconsistent with each other.

When adding a new archetype, the rule is: **every role key needs a
brief in `_static_role_briefs`**. A brief that says "this is the gold
answer" is a leak through the LLM. A brief that describes the role's
*function* (palliative / unconventional-target-acting / proxy-of-popular-
theory) is what we want.

### Archetypes intentionally not in this plan

- *Proxy metric hacking* — collapses into a special case of `hidden_cause`
  with two outcome heads. If we want a "myopic vs farsighted" test, we
  add a secondary question to a `hidden_cause` world rather than a new
  archetype.
- *Mediator classification* — the existing advanced bench tests this on
  static BNs. Re-doing it on simulator worlds adds noise but not a new
  ability.
- *Selection bias* — mechanically a fork of `confounded_action` plus
  `anomaly_discovery`'s mixture sampler. Revisit only if v2.5 needs more
  variety.
- *Synergy / combination effects* — interesting but encourages
  combinatorial query bursts that fight the cell budget. Deferred to
  v3 alongside multi-knob answer schemas.
- *Dose-response / non-monotonic threshold* — close to the existing
  advanced bench `advanced_budget_argmin` with extra noise. Add only
  if there's a clear partial-observability angle that the BN version
  cannot already test.
- *Invalid-action / non-intervenable rejection* — handled by the runtime
  query rejection rather than as a separate archetype. If the agent
  proposes `do(SeverityProxyA = low)`, the simulator rejects with a
  clear error message. That *is* the test.

## 6. Mixture prior

For each archetype we sample latent state as:

```text
B_i  ~ Bernoulli(ρ),  ρ ∈ {0.0, 0.10, 0.20}
Z_i  = structured_sample()  if B_i = 0
       uniform_sample()     if B_i = 1
```

Per-world ρ is balanced across the dataset. Validators check the gold
*under the mixed distribution*. The structured-only diagnostics are saved
to `hidden.diagnostics` for debugging but never used for scoring.

## 7. Noise calibration as an acceptance check

For every world, after construction:

1. Simulate `N_oracle = 50000` units under each candidate intervention.
2. For each measurement `m`, check
   `0.25 ≤ corr(m, latent_role(m)) ≤ 0.90`. If `m` is multi-cause, the
   correlation with each contributor must be ≥ 0.20.
3. Run the *small-budget naive baseline*: 80 obs-mode units + naive
   correlation analysis, repeated across 30 seeds. Must recover gold
   `≤ 40%` of the time.
4. Run the *medium-budget naive baseline*: 400 units under each candidate
   intervention with only the primary target proxy. Must recover gold
   `≥ 70%` of the time.
5. Reject the world if either band fails.

These bands define the "discovery actually matters" difficulty range.

The new static implementation is appended to `world_gen_rpg.py` under a

Functions added (all prefixed `static_rpg_`):

    # returns {"Y_target": ndarray, "Y_secondary": ndarray, ...}

Per-archetype, only two custom functions:

```python
def _static_rpg_apply_<archetype>(cfg, hidden, intervention_dict, eps) -> dict
def _static_rpg_observe_<archetype>(cfg, hidden, outcomes, measurements, eps) -> dict
```

A single `apply_interventions` call returns `Y` under whatever
`intervention_dict` is requested. For "compare every intervention" the
oracle calls `apply_interventions` once per candidate intervention with the
*same hidden state*, giving cheap counterfactual comparison from one set of
unit draws (CRN — common random numbers — for variance reduction).

### Runtime side

The runtime simulator in `framework_code/simulator_rpg.py` gains a
`StaticRPGSimulator` class (parallel to the existing `RPGSimulator`,
selected by `schema_version`) and three query handlers:
`observational_sample`, `interventional_sample`, `inspect_unit`. The
existing `RPGSimulator` is untouched.

### Audit side

`audit_rpg.py` gains a `--static` mode that:

1. checks schema version,
2. enforces public/hidden split (no latent var name in visible block or story),
3. re-derives gold from fresh oracle rollouts,
4. re-runs validators,
5. re-runs the recoverability band test,
6. smoke-tests each query mode.

## 10b. Optional LLM hooks (Opus 4.8 via Bedrock)

The deterministic, code-owned generation path is the source of truth.
Mechanism, oracle scoring, validators, and the recoverability band must
never run through an LLM. But two parts of a world *benefit* from being
written by a strong language model:

1. **Narrative polish.** Code-written stories and questions read like a
   schema. Opus 4.8 can rewrite the same information as a fluent briefing
   without changing the answer.
2. **Domain diversity.** Hand-curated templates cap diversity at three
   subdomains per archetype. Opus 4.8 can invent additional plausible
   subdomains so the dataset isn't always "GI clinic / orchard / payments
   risk."

Both hooks are off by default. They are added in `world_gen_rpg.py` and
gated by CLI flags:

```bash
python world_gen_rpg.py --static --llm-polish ...
python world_gen_rpg.py --static --llm-extra-templates 2 ...
```

Model defaults to `us.anthropic.claude-opus-4-7`
(`STATIC_LLM_DEFAULT_MODEL`), temperature 0.6.

### What the LLM is never told

- Oracle scores or `gold_answer`.
- Which intervenable knob is the true lever (or the assignment role of any
  variable — `decoy`, `weak`, `true_lever` role keys are internal-only).
- Validator output or recoverability rates.
- Hidden variable names (`LatentDriver`, `BackgroundStrain`,
  `HealthSeekingTrait`, `BaselineSeverity`, `DecoyState`, `LatentSeverity`).
- Mechanism parameters.

### Narrative polish (`--llm-polish`)

After `_static_build_<archetype>` produces an accepted world, the LLM is
handed only the **visible** block (story, question, observed variables,
intervenable variables with their values and current descriptions) plus
the archetype brief (`_STATIC_ARCHETYPE_BRIEF[archetype]`). It returns a
JSON object with rewritten `story`, `question`, and per-variable
`description` fields.

Hard rules enforced in the system prompt and re-checked in code
(`_static_polish_validate`, `_static_leakage_check`):

- Every input variable name appears verbatim in the output.
- The output question still demands a `do(.)` dict over intervenable
  variables AND a one-paragraph hypothesis.
- The output contains no internal role names or hidden-construct names.
- No knob is described as more or less plausible than another.

If the polish fails any check after `max_retries`, the world is written
with the un-polished narrative and `meta.llm_polish.applied = false`.
The world is never *rejected* because of polish failure — the underlying
generation is the source of truth.

### Template proposal (`--llm-extra-templates N`)

Before generation begins, the LLM is asked to invent `N` additional
subdomain templates per archetype. The LLM gets:

- the archetype brief,
- the required role keys (e.g. `primary_target_obs`, `decoy_knob_a`, …),
- one existing template as a *structural* reference,
- the list of already-used subdomains so it picks something different.

The response must satisfy `_static_template_validate`: every required
role key present, every variable name CamelCase and unique, every variable
name appearing in `knob_descriptions` or `measurement_descriptions`, and
the leakage check passing. Failed templates are dropped; successful ones
are appended to `STATIC_TEMPLATES[archetype]` for that run.

This lets the mechanism stay code-owned (the role → variable mapping
inside `_static_build_<archetype>` is unchanged) while diversity scales
without us hand-writing new templates.

### What this layer does *not* do

- It does not score hypotheses. Hypothesis scoring stays a downstream
  judge problem (see §14 caveat).
- It does not change `oracle.gold_answer`, `validators`, or the
  recoverability band.
- It does not run inside the validator loop. A world that fails
  mechanism-level validation never reaches the LLM.

## 11. Trustworthiness checks

Beyond per-archetype validators, every world must pass:

- **No latent-variable name** appears in `visible.story` or
  `visible.observed_variables[*].description`.
- **No `red_herring_interventions` indicator** leaks into the visible
  block. Knob descriptions are neutral and don't say "this is a placebo".
- **All measurement noise SDs** are within calibrated ranges.
- **Recoverability band** small ≤ 40%, medium ≥ 70%.
- **Oracle SE ≤ `MAX_ORACLE_SE_FRACTION × gold_margin`**.
- **Common-random-numbers consistency**: rerunning `oracle_score` with the
  same seed gives the same gold ordering.
- **Variable-domain enforcement**: simulator rejects out-of-domain values
  in interventions with a clear error message.

## 12. Diversity targets

- ≥ 4 different domain templates per archetype.
- Across the dataset, mixture weight ρ is balanced across {0, 0.10, 0.20}.
- True lever / answer is balanced across intervention-name positions so
  no single name is disproportionately the gold answer.
- For `hidden_cause`, the latent driver prevalence `p_present` is balanced
  across {0.40, 0.55, 0.70}.

## 14. Caveats

- **Hypothesis scoring** is human/LLM-judged only in v1. Auto-scoring is
  unreliable on free text and we don't want to bake in a weak proxy.
- **The cell budget will need tuning.** Start with the §3.4 defaults and
  shrink if naive brute-force still wins.
- **Red herrings have to be tempting, not absurd.** A red herring that
  obviously does nothing in observational data isn't a test. The
  `obs_truth_misleading` validator enforces this.
- **Mixture ρ ≤ 0.20**. Beyond that the structured signature can be
  diluted enough that even the oracle struggles.

## 15. One-sentence framing

The new generator produces **static, partially observed simulator worlds
without a pre-baked action menu**, where agents must discover a latent
cause or hidden subpopulation from noisy proxies under a tight cell budget,
propose a structured intervention (or anomaly characterization), and beat a
runner-up that the data would naively recommend.
