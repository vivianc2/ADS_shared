# One RPG v5 world, explained plainly

A walkthrough of a single generated world, written the way I'd explain it to my
partner over coffee. The world is
`out_v5_trial/world_bioreactor_yield_collapse_20260905.json`, generated by our
own `generate.py` (schema `rpg_scm_v5`). Nothing here is hand-made per world —
the generator makes them, audits them, and only keeps the ones that pass.

---

## 1. The one-sentence idea

We build a little fake universe where we secretly know *exactly* how everything
works (a set of equations), then we let an AI "scientist" poke at it through a
keyhole and ask: can you figure out what's really going on, and what to do about
it? Because we own the equations, we can score its answer with math, not vibes.

---

## 2. How the world is generated (the machine, not the hand)

Think of the world as a **flowchart of causes** (a graph). Each box is a
variable; each arrow is "this causes that," with a specific equation on it. Our
generator:

1. **Picks a template graph** (here: a bioreactor whose protein yield dropped).
2. **Jitters the numbers** a bit by random seed, so no two worlds are identical.
3. **Shuffles the action labels** — the "fix it" knob is called `RegimenF` in
   this world but `RegimenC` in the next, so the AI can't memorize "the answer
   is always knob C."
4. **Auto-calibrates the noise** so the honest clue is *visible but not
   obvious* (correlation ~0.5, not ~0.9), and the misleading clue is *tempting*
   (also ~0.5).
5. **Computes the correct answer** by brute-force simulation (try every dose,
   see what maximizes yield) plus a fine search for the exact best dose.
6. **Runs audits** and throws the world away unless it passes all of them:
   - names don't leak the answer,
   - the misleading clue really is causally inert (fake correlation),
   - the honest clue's signal strength is in-band,
   - **the "correct answer" can't be beaten by a sneaky combo** (a bug we caught
     and now guard against),
   - and the world is actually *solvable* with a few smart experiments.

So "generate more" = run the script with a new seed. It self-polices quality.

---

## 3. The variables — and who can see what

The full flowchart (what **we** know):

```
FeedWaterFlow (knob) ─┐
                      ├──► DissolvedCopper ──► ROS ──► CarbonFlux ──► ProductYield  (the outcome)
FittingCorrosion ─────┘        (hidden)     (hidden) (hidden)             ▲
   (hidden)                                                               │
                                                          small nudge     │
BatchSeedAge (hidden) ────────────────────────────────────────────────────┤
        │                                                                  
        └──► DissolvedOxygenReading  (a gauge the agent CAN read, but it's a red herring)

BrothProteinTurbidity  ◄── ROS      (a gauge the agent CAN read — the honest clue)
```

**The agent SEES** (the keyhole):
- **Outcome:** `ProductYield` (want it high).
- **5 gauges it can measure:** `ProductYield`, `DissolvedOxygenReading`,
  `TemperatureReading`, `FoamHeight`, `BrothProteinTurbidity`.
- **6 knobs it can turn:** `FeedWaterFlow`, `TemperatureSetpoint`, `pHSetpoint`,
  `RegimenF`, `RegimenD`, `AssayProbe`. Names are deliberately bland.
- A short **story**, the **question**, and its **budget** (12 experiments).

**The agent does NOT see** (behind the wall):
- The whole hidden chain: `DissolvedCopper`, `ROS`, `CarbonFlux`,
  `FittingCorrosion`, `BatchSeedAge`. These are never listed as variables. The
  real cause is *copper leaching from the new fitting* — and there is **no knob
  or gauge named "copper."** It must be inferred, never read off a label.
- The equations, the correct answer, and which gauge is honest vs. a red herring.

The split is literally the JSON structure: everything under `visible` is shown;
everything under `hidden` and `oracle` is never sent to the agent. The runtime
simulator (`sim_v5.py`) only ever hands over `visible` plus the *results* of
experiments.

---

## 4. What the agent can and can't do (the action space)

It can run four kinds of experiment, each costing one of its 12 queries:

| Experiment | What it does | Real-world analogy |
|---|---|---|
| `observational_sample` | just watch: measure gauges as-is | read the logbook |
| `interventional_sample` | set some knobs, then measure | run one batch at these settings |
| `sweep` | try a knob across a range, report the curve | a dose-response study |
| `clamp` | **force a gauge to a fixed value** and see if the outcome follows | the key trick — hold O₂ fixed to prove it's not the cause |

**Constraints we set (the "non-intervenables"):**
- It can turn **knobs**, but it **cannot** set the hidden variables (copper, ROS)
  — they aren't in the catalog at all.
- It can **clamp only `DissolvedOxygenReading`** — that's the one gauge we allow
  it to physically hold fixed (like a controller). Everything else it can only
  measure, not force. This is deliberate: clamping the red-herring gauge is the
  clean way to *prove* the red herring is fake, and we make that move available.
- It can set at most 3 knobs at once, and each has a legal range (continuous
  0–100, or on/off).

If it asks for something illegal (a knob that doesn't exist, a value out of
range, clamping a non-clampable gauge), it gets an error message back and the
turn is logged as an error — it doesn't crash and doesn't count against the
science.

---

## 5. How we tell the agent all this

Plain text in the prompt (see `run_agent_v5.py`). Each turn it receives: the
story, the question, the list of gauges and knobs (with ranges), the allowed
experiment types, its remaining budget, the result of its last experiment, and
its own running notes ("memory"). It replies with three blocks: `<reasoning>`
(its thinking), `<action>` (one experiment, or the final answer), and
`<scientist_memory>` (notes to itself for next turn). We log all of it.

We explicitly warn it in the system prompt: *names are neutral and don't reveal
the answer; a strong correlation can be a confound — test it; the best dose may
be in the middle, not the maximum; and a knob that moves the reading but not the
true state is a trap.*

---

## 6. The story the agent is shown (verbatim intent)

> A production bioreactor's protein yield fell ~30% over three weeks. It started
> after a maintenance shutdown where a feed-water line fitting was replaced.
> Operators suspect dissolved-oxygen drift or a temperature excursion. The broth
> looks cloudier than before. Feed and antifoam settings were unchanged.

Notice what's planted: the **real clue** (new fitting, cloudy broth) is mentioned
casually, while the **wrong suspects** (oxygen, temperature) are stated as the
operators' hunch. Exactly like a real lab where everyone's chasing the obvious
thing.

---

## 7. The question asked

Explain the hidden cause in plain language, cite your evidence, rule out
alternatives, name a decisive test, and **recommend the intervention and its
dose**. Also fill a small structured form: which gauge is the honest clue, which
are red herrings, and the sign (+/−/0) of each knob's real effect on yield.

We grade two things, and you must pass **both**:
- **(A) Did you pick a good intervention/dose?** — we re-simulate your
  recommendation and check its yield is within tolerance of the true best.
- **(B) Do you understand the structure?** — your structured form must match the
  ground truth on ≥80% of items.

---

## 8. The statistics hiding in here

This world is a compact lesson in causal inference:

- **Confounding.** `BatchSeedAge` drives *both* the oxygen gauge and yield, so
  oxygen and yield correlate (~0.5) even though oxygen has **zero** causal effect
  on yield. Classic "correlation ≠ causation." The only way to catch it is to
  **intervene** (clamp oxygen and watch yield not move).
- **Mediation / indirect effect.** The real cause (copper) is 3 steps upstream of
  yield. The honest gauge (turbidity) is a *mediator's shadow* — it moves with
  the hidden ROS. You reason about the cause through its downstream trace.
- **Effect-sign reversal (interaction).** Feed flow looks helpful in intuition
  ("more nutrients") but here it only leaches more copper, so more flow = worse
  yield. The sign is the opposite of the naïve prior.
- **Dose-response with an interior optimum.** The fix (chelation) helps up to a
  point, then over-treats and hurts. Best dose ≈ 66/100, not 100. This is a
  saturating-benefit-plus-toxicity curve — you have to *find the peak*, not push
  the knob to the wall.
- **Symptom masking.** One knob (`RegimenD`) nudges the *measured* yield up
  without changing the true state — a placebo/cosmetic effect. Watching only the
  outcome number gets fooled; watching the mechanism gauge doesn't.

## 9. How a human scientist solves it (≈5 experiments)

1. **Look first.** Measure yield, oxygen, turbidity. Notice oxygen tracks yield
   (tempting) *but* turbidity is high and also tracks low yield — the oxygen
   story doesn't explain the cloudiness.
2. **Kill the confounder.** *Clamp* oxygen high vs. low → yield barely moves.
   "Oxygen is a bystander." (This one move is what separates experts from the
   rest.)
3. **Dismiss the usual suspects.** Nudge temperature and pH → nothing happens.
4. **Follow the real clue.** Cloudy broth = cells stressed/dying, not starved of
   air; the story flagged the new fitting. Hypothesis: something toxic in the
   feed water.
5. **Confirm + dose.** *Sweep* the chelation regimen → yield climbs and turbidity
   falls together (a metal toxin, being mopped up), and the curve **peaks around
   66 then dips** → recommend that dose. Sweeping feed flow shows yield *falls*
   as flow rises → confirms the feed is the source.
6. **Don't get fooled.** Sweep `RegimenD` → the yield *reading* rises but
   turbidity doesn't improve → it's cosmetic, reject it.
7. **Answer:** hidden cause = metal contaminant from the new fitting stressing
   the cells; oxygen correlation is a batch-age confound; decisive test =
   chelation restores yield and clears turbidity; do chelation at ~standard dose;
   avoid cranking feed flow and don't rely on the cosmetic knob.

---

## 10. A likely SUCCESSFUL trajectory

Observe → clamp oxygen (see it's inert) → sweep the fix regimen coarse, see the
peak, **sweep again fine around the peak** to pin ~66 → sweep feed flow (confirm
reversal) → answer with the right cause, right structure, and dose ≈ 66. Passes
A and B. ~5–6 queries.

## 11. A likely FAILED trajectory (and it's an *interesting* failure)

This is close to what Opus 4.8 actually did in our first live run:

- It **did** the hard parts: clamped oxygen, ruled it out, found the flow
  reversal, identified turbidity as the honest clue → **passed part B (0.88).**
- But it **swept the fix on a coarse grid `{0,25,50,75,100}`, saw the peak at 75,
  and never refined** → picked 75 instead of the true 66. And it zeroed feed
  flow "to avoid contaminant," not realizing that once you chelate, flow no
  longer matters. Net: its recommended yield fell short of the true best →
  **failed part A.**

So it *understood the mechanism* but *missed the quantitative optimization* — the
exact expert-vs-agent gap we wanted to expose, and it's visible right in the
trace (coarse sweep, no refinement step). Other worlds may fail differently:
never clamping (mistaking the confounder for the cause), stopping after two
observations, getting the flow sign backwards, or falling for the cosmetic knob.
Each failure mode is a distinct, diagnosable bucket — not "the code broke."
